# 附录 C · ARENA：对抗式双 Agent 判据环境（规格，下一步；本次未实现）

**动机**：本作品的全部审计（A1–A8）是人设计的。要让"给尺子打分"成为 Agent 可持续运行的闭环，最小形态是一场两方博弈：

- **出题者 P**：用积木（字段 × 区域 × 统计 × 可选分母）提议一把尺子 M。
- **刷分者 G**：拿到 M 的定义与可见读数 V，在旋钮空间 K 里找配置，目标是把 M 做好看；命中缓存库零机时，库外真跑（每轮预算 n_new）。
- **裁判 H**：隐藏判分（MITgcm 真值 / 500 km 模态锚 / 零真值通道）判定 G 的配置是否"刷穿"了 M（M 变好、H 变差）。
- **反馈**：P 看到 G 的刷分轨迹（哪条旋钮、动了多少、H 怎么变），下一轮改尺子。

**终止与产出**：k 轮后输出 (M_k, 刷穿史)。三种结果都可写：P 收敛到某族（与穷举交集比对）；P 永远被刷穿（刷分策略的聚类本身是结果）；P 提出人未想到的尺子（用 A1–A8 复审）。

**资产已就位**：两个环境接口（env2.py / mk_case+analyze）、缓存库（345 + 29 + 56 条）、E43 的提议 harness、E45 的刷分 harness、A1–A8 审计脚本。预计每轮成本：风驱侧 ≤2 分钟 × n_new，内潮侧 ≤9 分钟 × n_new；LLM ≤¥1/轮。

**为什么这次没做**：复赛窗口内我们把时间给了第三强迫的证伪（E52）——先确认标量尺子不存在，再让 Agent 去找，才不会让它去追一个我们已知不存在的目标。
